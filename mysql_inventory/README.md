mysql_inventory — how to run
============================

This folder contains the MySQL variant of the data faker services.

Key files
- `docker-compose.yml` — Compose file to run services (orders-creator, supplier-creator, orders-modifier, orders-purger)
- `config.yml` — service configuration (DATABASE_URL, WAIT_TIME_MS, PREGENERATE_COUNT, etc.)
- Python services: `orders_creator.py`, `supplier_creator.py`, `orders_modifier.py`, `orders_purger.py`

Prerequisites
- Docker and docker-compose
- A reachable MySQL server (hostname/port in `config.yml`)

Quick start

```bash
cd /docker/sql-helper/mysql_inventory
# Build the images referenced by the compose file (compose uses repo Dockerfile by default)
docker compose build --pull
# Start orders-creator only
docker compose up -d --build orders-creator
# Tail logs
docker compose logs -f --tail=200 orders-creator
```

Configuration notes
- `config.yml` DATABASE_URL should use a PyMySQL DSN, e.g.:
  mysql+pymysql://sql_helper:Abcd1234@db01.kaskade.local:3306/inventory

- `WAIT_TIME_MS` is a millisecond range like `[1000, 15000]`. Services randomly pick a value between min and max before each iteration and log the chosen value.

- `PREGENERATE_COUNT` (under `supplier_creator`) controls how many suppliers are pre-generated by `orders_creator` at startup (orders creator will pre-generate suppliers if configured).

Troubleshooting
- If you see MySQL driver errors such as `Command Out of Sync` or `Lost connection to MySQL server during query`, ensure services do not reuse an engine created in the parent process after forking. The code in this repo disposes the parent engine after pre-generation to avoid those issues.

- If tables are missing, the services may auto-create minimal tables for convenience during development. For a production-like schema, run the project's `DDL.sql` against your database first.

Stopping services

```bash
docker compose stop orders-creator
docker compose down
```
